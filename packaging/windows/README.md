# Windows 本地开发与验收

## 环境基线

- PowerShell 7、Git、Maven 3.6 或以上、JDK 17。
- Node 24.15.0、npm 11.12.1；前端版本记录在 `jd-dbms-ui/.nvmrc` 和 `package.json`。
- 保留 Java 8 编译目标。本次不升级业务框架。
- 需要可用的元数据库和 Redis，数据库账号、密码、JWT 密钥及数据源加密密钥按 `doc/运行配置与密钥.md` 配置。

## 全新检出后的验证

在仓库根目录运行，按本机安装位置替换 JDK 路径：

```powershell
$env:JAVA_HOME = 'D:/code_env/jdk-17.0.20.1+1'
$env:Path = "$env:JAVA_HOME/bin;$env:Path"
mvn --batch-mode verify
Set-Location jd-dbms-ui
npm ci
npm run lint -- --quiet
npm run test:core
npm run build
Set-Location ..
```

前端锁文件必须随依赖变更一同提交；日常安装使用 `npm ci`。只有有意调整依赖时才使用 `npm install` 并审查锁文件差异。

运行中的后端会使用用户目录中的本地缓存。如果测试与服务发生缓存文件占用冲突，使用独立测试目录：

```powershell
mvn --batch-mode '-DargLine=-Duser.home=D:/jddbms-test-home' verify
```

## 启动

本地脚本读取根目录中被 Git 忽略的 `.env.docker`，再读取 `-ConfigFile` 指定的配置文件；非空进程环境变量优先。配置文件使用 `NAME=value` 格式，不执行文件中的代码。默认额外配置文件为用户目录下的 `.codex/jddbms-local.env`。

```powershell
./packaging/windows/start-local.ps1 -JavaHome $env:JAVA_HOME -CheckOnly
./packaging/windows/start-local.ps1 -JavaHome $env:JAVA_HOME
```

脚本将后端 JAR 复制到被 Git 忽略的 `.local/run/`，从副本启动，构建输出 `target/` 可以独立更新。日志也保存在 `.local/run/`。8080 或 28080 已被占用时脚本会停止，不会另外选择端口。启动命令返回后仍需确认健康接口和页面可访问。

- 页面：`http://localhost:8080`
- 后端健康接口：`http://localhost:28080/captchaImage`
- 前端版本：个人中心的“前端版本”，以及 HTML 中的 `jddbms-build` 元信息；有已跟踪文件未提交时会显示提示。Git 信息不可用的源码包会明确标识，不能视为某个 Git 提交的正式产物。

不要从正在运行的 `target/jd-dbms-admin.jar` 原地打包。更新本地服务时，先确认并停止脚本输出的前后端 PID，再执行启动脚本。脚本不停止已有服务、不修改数据库配置、不更换加密密钥。

## 浏览器回归

需要安装 `agent-browser` 及其浏览器，先启动前端：

```powershell
agent-browser --session sqlfix open http://localhost:8080
Set-Location jd-dbms-ui
npm run test:browser
```

该回归挂载真实 Vue 组件，使用模拟接口数据，检查 1000 行 × 300 列虚拟滚动、分页、排序、复制、自动列宽、拖拽、双击恢复、BLOB 按需读取、PNG 预览、NULL 和空文件。它不代表真实数据库或权限验收。执行失败或浏览器超时必须返回非零退出码。

发布前还需在已登录页面完成以下真实接口检查：

## 第二阶段：有效权限与共享授权审计（2026-10-15）

共享授权弹窗新增“有效权限”和“授权记录”。管理者可搜索用户或从已有用户授权行进入预览，分别查看平台角色、用户／团队／所有者授权来源，以及最终判定和拒绝原因。预览与实际接口复用数据源授权合并规则，停用账号不显示有效权限；角色授权与数据源授权仍取交集，目标数据库继续做最终校验。

用户／团队的授权、修改、撤销接入现有 `SYS_OPER_LOG`，成功和失败均记录。弹窗按连接 ID 关联最近 100 条共享授权日志，可查看操作者、时间、对象、权限和失败原因。预览和审计接口同样要求此连接的管理权限，数据库结构未改变。

真实回归需先启动服务，在 `agent-browser --session jddbms` 中以管理员登录，再运行：

```powershell
Set-Location jd-dbms-ui
node tests/sharing-live-qa.js
```

此脚本专用于本机“本地 DM”（连接 226）及已有 `TEST-TEST.BLOB_LARGE_TEST_20261015` 测试表，需数据库账号能维护 `JDDBMS` 中的临时团队。脚本克隆连接并创建临时平台用户／团队，使用正式登录与授权接口测试，在 `finally` 中撤权并删除测试对象，不修改原连接的共享授权。密码和令牌只用于浏览器内请求，不输出到测试报告。

本次真实回归 14 类场景通过：只读表查询、写入／任意 SQL 拒绝、非管理者访问拒绝、跨连接拒绝、自提权拒绝、多角色与团队、授权叠加、团队停用、移除成员、团队即时撤权、用户即时撤权、停用账号会话失效、预览与角色限制一致、成功／失败审计。清理后核查无有效临时用户和临时团队残留。界面实测了用户搜索、8 种动作预览、标签切换和审计空状态。

前端核心回归增至 37 项，覆盖预览请求竞态、撤权刷新、连接切换清空和审计错误反馈。后端补充预览与执行判定一致性、授权来源叠加、撤权、账号停用、私有连接／所有者限制及新接口管理权限测试。这里的审计关联针对数据源共享授权；跨 SQL、迁移和平台操作的统一请求链路仍属于后续扩展。

## 全角色权限回归（2026-10-15）

开发角色 `lyc` 打开自有连接“测试”失败，暴露出先前仅使用合成权限测试的覆盖不足。本次明确所有者无需给自己额外授权，实际动作仍受平台角色限制；其他人的共享连接继续要求显式授权，不修改真实账号的角色、连接归属或授权记录。

左侧打开表、视图及表格筛选／翻页改用受控的表查询接口，避免把只读角色误判为需要任意 SQL 执行权限。表名由元数据接口引用，筛选仅接受表达式，拒绝额外语句、UNION、INTO 和 FOR UPDATE；只读查询结果不允许编辑。共享管理按钮采用后端实际判定。另修复带连字符模式的 DM 删表语句、平台接口权限拒绝误报系统异常，以及创建账号允许 30 字符但登录仅允许 20 字符的不一致。
