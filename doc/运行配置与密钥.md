# 运行配置与密钥

项目不再在源码中保存数据库口令、JWT 密钥或 SSO client secret。部署前必须通过环境变量提供以下配置。

## 必填变量

| 变量 | 用途 | 要求 |
| --- | --- | --- |
| `JDDBMS_META_DB_PASSWORD` | 系统元数据库密码 | 使用独立低权限账户 |
| `JDDBMS_TOKEN_SECRET` | JWT 签名密钥 | 使用随机生成的长密钥 |
| `JDDBMS_DATASOURCE_ENCRYPTION_KEY` | 数据源密码 AES-GCM 主密钥 | 至少 32 个字符，部署后必须稳定保存 |

`JDDBMS_DATASOURCE_ENCRYPTION_KEY` 丢失后，新格式的数据源密码无法恢复。该密钥不得写入 Git、日志或普通配置文件，应由部署平台的 Secret 管理能力注入。

## 可选变量

- 元数据库：`JDDBMS_META_DB_URL`、`JDDBMS_META_DB_USERNAME`
- Redis：`JDDBMS_REDIS_HOST`、`JDDBMS_REDIS_PASSWORD`
- Druid 控制台：`JDDBMS_DRUID_CONSOLE_ENABLED`、`JDDBMS_DRUID_USERNAME`、`JDDBMS_DRUID_PASSWORD`
- 达梦 DMP：`JDDBMS_DM_DMP_USER`、`JDDBMS_DM_DMP_PASSWORD`、`JDDBMS_DM_EXPORT_TOOL`、`JDDBMS_DM_IMPORT_TOOL`
- Oracle DMP：`JDDBMS_ORACLE_DMP_USER`、`JDDBMS_ORACLE_DMP_PASSWORD`、`JDDBMS_ORACLE_EXPORT_TOOL`、`JDDBMS_ORACLE_IMPORT_TOOL`
- SSO：`JDDBMS_SSO_CLIENT_ID`、`JDDBMS_SSO_CLIENT_SECRET`

## 迁移说明

历史数据源密码仍可用旧 DES 格式读取；新建或修改数据源时会写入以 `v2:` 开头的 AES-GCM 密文。全部数据源重新保存并验证后，才能删除旧格式兼容逻辑。

原始源码曾包含元数据库、DMP、JWT 和 SSO 示例凭据。首次部署本版本前必须轮换这些凭据，不能继续使用历史值。

DMP 工具要求把登录信息作为本机进程参数传入。应用日志和接口已经脱敏，但同一主机上的高权限操作系统用户仍可能看到进程参数，因此运行主机必须限制登录权限。
