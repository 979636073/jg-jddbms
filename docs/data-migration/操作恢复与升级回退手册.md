# 数据迁移操作、受限恢复与升级回退手册

适用当前功能开发版本。先核对 [功能支持矩阵](支持矩阵与发布门槛.md)。用户要求商业工具级功能，不要求商业发布；本手册说明安全使用与恢复，不作生产 SLA 承诺。

## 1. 迁移前准备

- 使用有权限的源/目标数据源。目标模式、表空间、账号和授权由数据库管理员预先准备；系统不复制账号/口令，也不自动提权。
- 冻结源端数据与结构，停止目标所选对象业务写入。当前不是 CDC 或不停机迁移，没有跨表业务快照保证；非冻结场景不得执行。
- 备份具体目标表的数据、结构、索引/约束、触发器、引用和授权，验证可恢复；特别是清空/删除重建。系统的 DDL 预览不是备份。
- 同类库同名模式且源/目标对象重叠时保守阻断；连接名/ID 不同不证明物理对象不同。改用明确独立目标对象，不绕过检查。
- 禁用 SSH 隧道数据源迁移；当前执行器只允许单后端实例、单迁移任务，勿运行多个实例争抢 TASK。工作区窗口不充当迁移连接。

## 2. 六步执行

1. 打开个人中心管理导航“数据迁移”，新建名称，选择已保存的数据源，分别点击连接。只读显示版本/驱动，不在迁移页编辑连接口令。
2. 选源业务模式及对象。切换模式、搜索和翻页保留选择，最多 100 个对象。整模式不是隐式全选；依赖对象要一并选择。
3. 选默认目标模式，必要时覆盖对象模式/名称。在“字段 / 策略 / 筛选”中配置单对象范围、目标策略、字段改名及最多 20 个 AND 条件。留空策略继承任务默认；改变默认范围可能导致覆盖策略不兼容，预检查会阻断。字段不能省略，改变类型需显式配置转换并审阅确认，不支持的类型不能静默降级。
4. 非表对象打开“转换目标 DDL”：读源定义，逐对象填写 `CREATE 类型 "目标模式"."目标对象" ...` 并明确确认。禁止 OR REPLACE/任意批量脚本；包规范和包体以独立行 `/` 分隔。动态 SQL 依赖由操作者补充。目标语法、业务含义、序列安全起点、触发器行为由操作者审阅，编译有效不等于业务语义等价。
5. 运行预检查，逐个查看阻断和 DDL/字段映射。索引/约束/外键都在预览中，重建时还显示旧目标结构。修改配置或超过 10 分钟后重新预检查；启动时服务再检查。被阻断的对象不能绕过。
6. 审阅目标清单、离线条件及高风险备份确认后启动。关闭页面不取消后台任务；在结果页观察实际阶段/已确认提交/校验/错误，下载 JSON 报告留档。

报告保存在 TASK 中，配置引用数据源 ID，不保存连接口令或 JDBC URL；不持久化搬运的业务行或恢复读取的主键值。人工筛选值会随配置和报告保存，DDL 也可能含敏感文本，报告必须按敏感配置管理，不能称完全脱敏。

### 数据筛选与节流

筛选使用源字段名（不是改名后的目标字段）。支持数值/文本/无时区时间的 EQ、NE、GT、GE、LT、LE，文本 LIKE（% 和 _），以及 IS NULL / IS NOT NULL。不接受 SQL、OR 或自定义表达式，值通过 JDBC 绑定。时间使用 `yyyy-MM-dd HH:mm:ss`，可加最多 6 位小数，年份 0001～9999；空值选 IS NULL，不以空字符串代替 NULL。

空筛选读取全表；否则源基线、读取、校验及恢复主键查询均使用相同 AND 条件。目标摘要覆盖完整目标，追加另加原目标基线。外键需要的父数据不会自动补齐，缺失导致约束失败时不能标记全部完成。仅结构不能保留筛选，需手动移除条件，不静默丢弃配置。

复制行速率 0 不限，1～100000 行/秒用于整个任务共享节流，不随表并发数相乘。首行立即允许，后续行按间隔准备写入；提交批次上限为配置批次与一秒速率中较小者，允许批次内突发。等待可取消，约 100ms 检查取消；不限制单行 LOB 网络字节，不承诺阻塞语句瞬时取消。

表级并发默认 1，可选 1～4。每个表写入器独立持有源/目标连接；含 LOB 的表共享一个执行槽，不同时复制多个 LOB 表。显式业务依赖按完成波次执行，索引/约束和程序对象在数据完成后执行。当前仍每后端单任务；最大发起 1 组协调连接 + 4 组工作连接（源/目标共 10 个，不含 TASK/HTTP 等连接），应按数据库资源选并发。取消或停止后等待所有写入器退出才记录终态，不提前释放活动任务。

### 表空间及显式类型转换

默认及单表目标表空间只能选择当前目标用户可见的在线永久表空间；留空用目标默认。只用于新建/重建表，不移动仅数据模式中的既有表，不创建表空间、不增加配额或授权；写入时空间/权限不足仍可能失败。不是索引/物理布局克隆。

字段转换支持 `NUMBER(p,s)`、`VARCHAR(n)`、`NVARCHAR(n)`、`RAW(n)`、`TIMESTAMP(0～6)` 的受限 CAST；可填写最多三层对象标量属性路径。每次修改转换或属性后须重新勾选“已审阅转换”。不接受任意表达式，不自动序列化整个 UDT。未转换类型、转换字段的非空默认值、同时筛选转换字段等情况仍阻断。完整摘要核对的是转换后的值，舍入/截断或只取一个属性不是原类型无损；转换主键不能按旧目标受限续迁，应使用新目标重新迁移。

## 3. 目标策略

| 策略 | 适用 | 已有目标的处理 |
| --- | --- | --- |
| STOP（默认） | 结构/全量，或仅数据 | 结构同名阻断；仅数据必须兼容空表 |
| SKIP | 结构/全量 | 同名对象跳过，不修改；整体 PARTIAL，不计全部验收 |
| APPEND | 仅数据 | 兼容已有表，绑定 INSERT；不做 upsert，主键/唯一冲突会失败；核对原目标 + 源数据的合并摘要 |
| CLEAR | 仅数据 | 精确目标表 TRUNCATE 后写入，原数据不可由任务取消恢复 |
| REBUILD | 结构/全量普通表 | 精确 DROP 后重建，不 CASCADE；计划外 FK 引用阻断，不自动禁约束/触发器 |

后三种必须独立确认目标清单和备份。单表范围/策略可覆盖默认，审阅以实际策略为准，覆盖不能绕过确认。程序对象只支持阻断/跳过，不能借表策略替换程序。外键可能使 TRUNCATE 失败；遇错停止，不擅自解除引用。

当前 REBUILD 对目标父表的既有引用采取保守阻断，即使引用表也在本次计划内，也不自动拆除外键或改写删除顺序；需要由管理员先准备明确无引用的新目标对象。不能据此宣称任意带外键整库可原地重建。

## 4. 结果解释和取消

- COMPLETED：所选对象通过本版对应逻辑结构/完整内容摘要/对象有效性检查。程序为人工转换，不证明任意程序语义等价。
- PARTIAL：存在跳过、失败或依赖阻断，不是全部验收。
- FAILED/CANCELLED/INTERRUPTED：未完成；已经提交的行和 DDL 仍可能存在。
- NEEDS_REVIEW：提交、DDL 或持久化记录结果不确定；必须人工核对，再通过受限检查与明确确认，禁止直接重跑。
- 追加时源行数和目标行数通常不同；合并摘要验证的是保留旧行后的预期内容，而非要求源=目标。

点击取消后在数据库响应/批次安全边界生效，回滚未提交批次；当前语句超时 300 秒，不承诺瞬时取消。LOB 按流读取，读取量包含校验等读取，不是单向网络吞吐。禁止用估算百分比代替完成判定。

## 5. 受限恢复

1. 先保存报告，核对已提交行、对象归属、已执行 DDL、不确定提交以及备份；保持源与目标冻结。
2. 点击“恢复检查”。系统核对原筛选范围内的源端全量/结构基线、稳定主键、目标结构及现有行；目标主键行必须与范围内源行一致，范围外/额外/冲突/重复键即阻断。即使范围外目标行与未选择的源行完全相同，也不自动接管。
3. 检查通过后仍需“确认并恢复”。恢复启动再核对授权、内容及有效期；已有匹配行复用，缺失行才写入，不更新、不覆盖、不删除。
4. 恢复为有界全表复扫及主键核对，不是 OFFSET/ROWID 游标续传；恢复检查/大 LOB 校验需要时间。批次提交及控制库记录不是跨库原子事务。

以下不能自动恢复：无支持类型的稳定主键、无旧基线、源结构/内容变化、目标既有行变化、未持久确认对象归属、未记录却已存在的索引/约束、追加、仅结构及程序混合任务。程序创建成功但检查点丢失也不能自动接管同名对象。

结果页的“检查并重跑该表”仅用于未完成普通表。检查将绑定任务、源对象标识和十分钟有效期；确认后再次检查，只执行该表及其尚未完成的索引/约束，不自动重跑依赖或已成功对象。依赖未完成时须先处理依赖。重跑次数和原结果摘要保留在审计日志，其他未完成对象不会随该表成功而被标为完成。

单表重跑允许从程序混合任务中选择符合条件的普通表，但仍不自动恢复程序对象；无稳定键、追加、仅结构、无基线或目标归属/内容不一致均阻断。整个程序混合任务的恢复仍阻断。

不能安全续迁时，可在结果页选择一个未完成对象（留空选择所有未完成对象），点击“重新迁移到新目标”。系统生成关联原任务的新草稿，纳入必要依赖、分配新名称，原目标及成功记录不删除。必要依赖即使原任务已成功，也会复制到新的独立目标，不重复写入原成功目标。

新草稿从完整流程开始：重新连接、核对范围/名称、预检查及确认后执行，不立即写入。无主键、无旧基线、仅结构、失败程序等可走此流程，但不补假检查点、不盲目接管旧目标。程序目标 DDL/确认会清空，必须重新编辑新对象引用；追加失败不会自动再次追加。源冻结仍是前提。旧目标的保留、备份恢复或清理由操作者依据报告另行决定。

### 执行遇错策略

默认仍遇错停止。选“继续独立对象”后，只有明确的 SQL 数据/约束/语法错误（SQLState 22/23/42，异常链也须满足）才允许在成功回滚未提交批次后继续；不丢弃坏行。已提交数据及 DDL 保留，失败对象记 FAILED，依赖对象记 DEPENDENCY_BLOCKED，任务记 PARTIAL。晚于数据复制的约束失败也会使已复制的依赖对象变为未验收，而不会撤销其已提交数据。

超时、断连、事务冲突、未知 SQLState、回滚失败、控制库检查点失败、源端变化或校验差异等仍停止；取消不受继续策略影响。DDL 执行前持久记录 DDL_COMMITTING，未确认结果或服务在此阶段中断时进入 NEEDS_REVIEW。不把所有异常当作可安全继续的对象错误。

## 6. 升级与回退

本轮没有替换现有容器。实际发布前完成相应环境验收并另行执行部署：

1. 停止接受新迁移；所有活动任务结束或明确取消，并保留报告。确认没有 RUNNING/CANCEL_REQUESTED 后再切换版本，不在批次提交时主动升级。
2. 备份控制数据库 TASK 和相关数据源配置、持久卷、加密密钥、应用环境配置及具体目标数据库；密钥离线安全保存，不放 Git/日志/报告。
3. 记录旧代码 commit、镜像 tag/digest、JVM/CPU 架构和配置。保留旧镜像及卷，不清理“看起来不用”的回退版本。新 jar/dist 需作为同一发布版本，避免 API/页面不一致。
4. 此实现复用现有 TASK JSON 内容，没有新增正式数据库表/DDL 升级脚本。先在备份或隔离环境验证快照兼容、启动、权限、任务查看和一项小规模迁移，再按明确发布指令更新容器。
5. 如失败，停止新任务并核对其目标效果；确认无活动迁移后恢复旧应用镜像/前端和配置。**镜像回退不撤销目标 DROP/TRUNCATE/INSERT，也不回退控制库中的新任务。**数据库恢复必须单独由管理员按备份及审计执行。
6. 升级后创建的复杂任务不要交给旧迁移逻辑执行。执行中过的任务配置只读，不通过手改 TASK 绕过状态。必要时保留新报告，在旧版新建仅其已验收范围的配置。

## 7. 开发回归复现

实库测试仅显式启用后连接已有专用 QA 数据源，不在默认单元回归中自动访问数据库：

```powershell
$env:JAVA_HOME='D:\code_env\jdk-17.0.20.1+1'
# 先通过安全环境设置元数据库及加密密钥，勿复制到文档或终端日志。
$env:JDDBMS_MIGRATION_LIVE='1'
mvn -pl jd-dbms-bisnuess -am '-Dtest=Migration*Test' '-Dsurefire.failIfNoSpecifiedTests=false' test -q
# 上一命令完成后再打包，不能同时修改共享 target。
mvn -pl jd-dbms-admin -am '-DskipTests' package -q
```

ARM QA 用现有 ARM64 运行时独立 `docker run --rm --platform linux/arm64`，挂载新构建只读、测试 target 可写；`-Xmx256m --memory 512m --cpus 2`。测试通过 Boot PropertiesLauncher / JUnitCore 加载新业务代码，另在独立容器迁移过程中 SIGKILL，再启动新 JVM核对并恢复。HTTP 测试启用 `JDDBMS_MIGRATION_HTTP=1`，需独立 Redis QA 的 36379 端口；复用现有 SecurityConfig/JWT/Redis，登录用户服务为隔离 QA 实现，不是完整生产用户表/验证码验收。上述测试不替换现有应用，不代表物理 ARM 性能。

实库 fixture 使用本次精确随机 `JD_QA_*` 或 `JQA_*` 名称，测试后清理；Oracle QA 表使用 PURGE，不可从回收站恢复。用户已授权准备 QA 环境：为既有专用 Oracle QA 用户补充对象创建权限；边界测试创建随机临时 QA 用户，只调整该临时用户的权限/配额，测试后删除该用户及其专属对象。不开启默认提权，也不改变业务用户。
