# 数据迁移方案与功能验收基线

状态：方案及样稿已确认。2026-09-29 用户澄清：目标是达到商业工具级的功能完整度，不是商业发布。许可、发布签字和生产 SLA 不作为本轮开发阻塞；安全默认值、真实功能及故障测试仍保留。当前实现和实际测试范围见 [开发与回归记录](开发与回归记录.md)、[功能支持矩阵](支持矩阵与发布门槛.md)，不以此宣布任意版本/对象兼容。

## 1. 范围与前提

- 在个人中心所在的管理导航中增加“数据迁移”独立页面，不塞进个人资料表单。
- 四个迁移方向：DM → DM、DM → Oracle、Oracle → Oracle、Oracle → DM。
- 建议首版为全量离线迁移，支持仅结构、仅数据、结构与数据；不是持续复制或 CDC。
- 迁移期间需冻结源端数据及结构变更，目标端业务不得同时写入所选对象。若业务不能停写，另行设计一致性快照及增量补齐方案，不能用多次普通 SELECT 宣称整库一致。
- 当前 Oracle/DM 测试环境用于功能验收。尚未测试的版本、字符集、规模、运行资源和停机指标不作兼容或吞吐承诺，不要求用户先完成商业发布条件才能开发功能。
- 不改变已暂停的 DMP 导入导出功能，不要求上传 DMP，不依赖图形 DTS 客户端。

## 2. 参考依据与实现方式

参考 DTS 的连接、对象选择、类型/对象映射、策略、任务审阅及执行报告流程。DTS 官方说明将对象结构转换与数据读取/写入分开；本系统据此采用 JDBC 双端直连和独立的目标方言生成。

- [DTS 迁移配置与原理](https://eco.dameng.com/document/dm/zh-cn/pm/dts_migrate.html)
- [Oracle 移植到 DM：静态迁移与一致性前提](https://eco.dameng.com/document/dm/zh-cn/start/oracle_dm)

以上为流程参考，不表示本系统调用、嵌入或已获得 DTS 的商业授权，也不表示官方工具原生覆盖 Oracle → Oracle。四方向能力由本系统分别实现并验收。

## 3. 界面与用户流程

沿用现有 Vue/Element UI、蓝白配色、12px 正文，视觉扩展而非重设计。完整视觉规范见同目录 DESIGN.md。

入口：个人中心管理导航 → 数据迁移。

首页是任务列表：名称、方向、源/目标连接名、状态、当前阶段、已提交行数、失败对象、创建时间和操作。提供新建、查看、复制配置和报告；不恢复已经移除的任务中心入口。

新建采用占满内容区的向导，不用窄小弹窗：

1. **基本信息与连接**：名称、描述、已有源/目标数据源；按需检测连接、版本、驱动、字符集、权限。迁移连接独立于工作区 SQL 会话。
2. **范围与对象**：按需展开模式与对象；支持多模式、搜索、分页、选中数量和依赖提示，默认排除系统对象；整模式只迁移明确选中的业务对象。
3. **映射与策略**：模式/表空间/对象/列名称映射、列类型/长度/精度/标度映射；默认值、注释、约束；结构/数据开关、数据筛选、冲突、批次及并发设置。全局策略可被单表策略覆盖。
4. **评估与预检查**：列出可直接迁移、需转换、需人工处理、阻断项；显示源 DDL 与目标 DDL、类型损失和依赖缺失。此阶段只读，不执行目标 DDL/DML。
5. **审阅并执行**：展示最终对象清单、预检查版本、风险与目标改动；阻断项未解决不能开始。提交后后台执行，页面关闭不终止任务。
6. **结果与验收**：总览、对象进度、错误、日志、校验差异、报告；错误定位到对象/阶段/批次，复杂对象显示编译结果，不只有“上传成功”式提示。

向导草稿保留，但修改连接、对象、映射或策略后必须使旧评估失效。开始时再次核对权限及元数据漂移。

## 4. 对象与类型支持边界

| 对象 | 基础闭环 | 功能支持边界 |
| --- | --- | --- |
| 普通表及数据 | 四方向；字段、注释、可支持的默认值、空值语义 | 未识别的表特性阻断，不静默去掉 |
| 主键、唯一约束、普通索引、检查/外键 | 分阶段生成与校验；依赖闭环 | 函数索引、特有聚集选项需独立转换与验收 |
| 序列、视图、同义词 | 独立对象迁移与依赖处理 | 序列状态、跨模式引用、视图可用性必须验证 |
| 触发器、过程、函数、包 | 采集、兼容性评估、SQL 预览与人工修改入口 | 按四方向/版本逐项支持，编译失败不得标成功；不承诺任意 PL/SQL 自动无损转换 |
| 分区表、物化视图、虚拟/自增列、用户定义类型 | 识别并报告 | 明确支持规则或人工替代，降级为普通表必须用户主动同意 |
| 用户、角色、授权、系统任务、物理存储属性 | 不默认复制 | 目的用户/表空间预先准备，权限和物理路径另行审核，不复制口令 |

基础类型覆盖字符/国家字符、数值、日期/时间、RAW、BLOB、CLOB、NCLOB（按具体驱动能力验收）。重点检查字节/字符长度、负标度、数值范围、浮点特殊值、时区、空字符串与 NULL、CHAR 尾空格。

未支持类型必须阻断或由用户明确指定可验证的转换，不能统一转 VARCHAR 或默默截断。新增目标列、生成列、自增列等按目标数据库规则处理；LOB 采用流式传输，不经前端 Base64，不全量载入内存。

## 5. 执行与可靠性

- 按依赖顺序：预检查 → 表结构及必要主键 → 分批迁移数据 → 剩余索引/约束 → 依赖对象 → 校验。触发器默认最后创建，避免导入数据触发副作用。
- 源/目标各持有独立 JDBC 连接；不靠反复切换工作区线程上下文来操作双库；后台线程显式绑定权限与任务身份并在结束时清理。
- 前台只提交配置和读取进度，不传输业务数据；执行使用有界并发、批次行数与字节上限、读取批次、提交批次、LOB 单独限制和限速。
- 显示阶段、读取/写入/已提交行数、耗时、速率和错误对象。总量未知时显示未知或估算，不生成虚假的精确百分比/剩余时间。
- 任务、对象状态、配置快照、DDL、批次及执行结果持久化。重启后标识中断任务，不自动把 PROCESSING 判成成功，也不未经恢复检查就重新执行。
- 取消在安全边界生效，关闭读取游标并回滚未提交事务；已提交数据和已完成 DDL 不承诺全任务原子回滚。报告必须清楚列出已生效的目标改动。
- 默认遇错停止；用户可选择继续独立对象，但依赖失败对象不得继续。批次部分失败要回滚后再定位错误行；默认不丢弃坏数据。
- 有稳定唯一键且源端冻结时，才可采用稳定键游标与经验证的幂等写入/恢复策略。控制库检查点与目标事务并非天然原子提交，提交结果不确定时进入“待核对”，禁止盲目重试。
- 无稳定唯一键的表不承诺安全行级断点续迁；允许在明确授权并确认只影响本任务专属目标对象后重新迁移该表。目标已有业务数据或无法判定提交状态时要求人工核对。
- 不将 ROWID 当跨库业务主键，不用 OFFSET 作为有并发变更数据的可靠检查点。

## 6. 安全默认值

- 源端只读；选择源/目标时都执行后端权限校验，日志、报告和任务详情按所属用户隔离。
- 默认目标同名对象冲突即阻断。可选跳过、兼容结构追加、清空数据后迁移、删除重建；结构和数据策略分开显示。
- 清空/删除重建为高风险操作，必须展示具体目标对象并二次确认；不默认 TRUNCATE/DROP，不自动关闭外键或触发器。DDL 的隐式提交/恢复限制须按版本测试并提示。
- 校验源与目标是否实际上指向同一数据库/模式/对象；连接别名不同不代表两个库。不能确认身份时不允许对同对象执行破坏策略。
- 不向前端返回口令、带口令的 JDBC URL 或后台异常里的凭据。配置保存数据源引用，报告不包含密码。
- DDL 与数据绑定分开；标识符按方言转义，普通数据使用预编译参数。首版筛选只开放已支持的结构化条件，不把任意 SQL 当作安全条件拼接。
- 同目标对象禁止并发迁移任务，重提开始请求不能重复启动；执行中的计划不可编辑。
- 仅参考流程和信息要素，不复制第三方代码/图标/品牌资产；正式打包前核查数据库驱动及第三方组件的许可与分发条件。本设计不构成商用合规认证。

## 7. 校验与功能验收

最终报告包含计划范围、显式排除项、版本/驱动信息、配置版本、已执行目标 DDL、已提交行数、对象/数据校验结果、错误及恢复操作。源库/目标版本和对象支持矩阵随版本发布。

- 四方向分别在独立测试模式验证；不能用 Oracle → DM 通过代替其他方向。
- 表结构、对象数量、注释、索引和约束比较；依赖对象检查存在性、有效性及编译错误。
- 按同一筛选条件核对源目标行数。精度/日期/字符/NULL 使用规范化值比较；LOB 比较长度及内容摘要。仅行数一致不足以宣布数据一致。
- 有唯一键时按键分段做完整校验；无唯一键时采用保留重复次数的规范化多重集校验。抽样结果明确标为抽样，不能算全量验收通过。
- 空表、无主键、复合主键、大小写/中文/保留字标识符、大数/负标度、时区、NULL/空 LOB、长文本、二进制均有用例。
- 注入网络中断、提交不确定、目标空间不足、权限失败、取消、浏览器刷新、容器重启、重复提交、约束失败；验证不会误报成功或无提示产生重复数据。
- 在约定最大数据量/LOB/单表规模和 ARM64 容器资源下实测耗时、峰值内存、连接数与停机窗口；不预先虚构吞吐 SLA。
- 功能验收包含越权拒绝、日志脱敏、停止/恢复和升级/回退说明；真实业务备份与切换是实际操作时的前提，不属于本轮商业发布签字。数据迁移通过不等于应用 SQL 和性能适配完成。

## 8. 分阶段开发与验收

1. **设计确认与 v0**：确认离线边界、首发版本、数据规模和对象范围，展示可点击向导/任务页样稿。验收：入口、步骤、密度、风险展示符合现有界面。
2. **四方向基础闭环**：数据源权限、元数据和预检查、普通表结构及批量/LOB 数据搬运、后台任务和基础校验。验收：四方向独立真实测试模式中数据与类型正确、源库无写入。
3. **对象与策略完善**：模式/字段映射、依赖、索引/约束/序列/视图、复杂对象评估和人工脚本处理、目标冲突策略。验收：逐项公布自动/人工/不支持清单，失败可定位。
4. **任务恢复与安全验收**：取消、重启中断识别、幂等/受限续迁、错误对象重跑、完整报告。验收：故障注入后无误报、无盲目重试、越权被拒绝。
5. **工具级功能收尾**：支持矩阵、全量校验、资源基线、ARM64 隔离环境、升级/回退和操作手册。验收：实测功能可用、故障不误报、限制有据可查；不是商业发布或生产 SLA 认证。

每阶段保留独立验收证据。先建成并验收四方向闭环，不把界面按钮、模拟进度或某个数据库对的小样本测试当整体完成。

## 9. 已确认范围与未承诺范围

- 已确认全量离线、现有蓝白样式及六步向导；功能开发与测试继续，不重新等待样稿或商业发布审批。
- 用户授权自行准备独立 QA 账号和权限，只用于测试；不改业务库授权或配额。
- 复杂程序对象采用人工转换与有效性检查，未知类型默认阻断；显式 CAST/标量属性投影需主动确认业务语义。
- 未承诺不停机增量、任意程序自动转换、未测版本/字符集及最大规模/物理 ARM 吞吐。实际部署时再按具体环境验证，不将其作为本轮功能开发阻塞。
