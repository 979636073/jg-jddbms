# 第四阶段：持续监控与发布恢复（2026-10-15）

## 本阶段行为

- 后台每 30 秒调度已启用的 DM／Oracle 连接；默认关闭，保存配置后开始采集。采集使用两个工作线程和有界队列，同一连接不会重叠采集。采集耗时或排队可能延长实际间隔。本阶段用于单实例运行。
- 阈值按连接保存到元数据库；开启、关闭和修改阈值要求同时具备此连接的 `MONITOR_VIEW` 与 `DATASOURCE_MANAGE`。配置操作写入现有操作日志。
- 每次后台采集重新读取配置者的账号状态、平台权限和连接授权；失效时记录采集异常，不访问目标数据库。恢复权限后可继续采集。
- 保存汇总指标、告警触发／最近触发／恢复时间；不保存会话用户、客户端地址或 SQL。连续命中合并为一个告警事件。读取失败保留未知值，不以缺失指标恢复告警；部分表空间不可读时，已知超阈值文件仍会触发容量告警。
- 样本和已恢复告警保留 7 天，未恢复事件继续保留。页面展示最近 200 次采集和最多 100 条告警，未恢复优先；提供趋势缩放。关闭采集不等于告警恢复。
- 原实时快照接口保留。实时连接失败不会隐藏已持久化的历史。切换连接、组件销毁后的旧响应不会覆盖当前状态，自动刷新不会覆盖尚未保存的同版本配置草稿。

## 复跑

管理员在 `agent-browser --session jddbms` 登录 localhost:8080 后：

```powershell
Set-Location jd-dbms-ui
npm run test:core
npm run lint -- --quiet
node tests/roles-live-qa.js
node tests/sharing-live-qa.js
node tests/monitor-live-qa.js
```

监控验收通常需要跨一个调度周期及 32 秒停止观察期。脚本仅创建临时连接，默认在 `finally` 清理；`--keep-for-restart` 是人工重启验收选项，保留的连接 ID 会写入报告，验收后需关闭采集并删除对应的三张监控表记录和克隆连接。

H2 恢复脚本回归：

```powershell
./packaging/h2/test-import.ps1 -H2Jar '<H2 2.2.224 jar>' -Java '<JDK17>/bin/java.exe'
```

本次备份与隔离恢复文件位于 `D:/code/_backups/jg-jddbms-phase4-20261015/`，不加入 Git。备份是逐表导出，运行期间变动的表不保证跨表一致性；生产恢复应使用停写窗口或数据库原生一致性备份，并单独保留配置密钥。

## 数据库升级与回退

新增 `DB_MONITOR_CONFIG`、`DB_MONITOR_SAMPLE`、`DB_MONITOR_ALERT` 三张元数据表。首次启动自动补建缺失表；新 H2 库的建表脚本也包含这三张表。应用账号需要建表、建索引权限；由 DBA 预先执行时可使用 `sql/20261015_database_monitor_dm.sql`，该脚本只执行一次。已有业务表未变更。

本阶段应用回退保留新增表，旧版忽略这些表；重新发布后记录继续可用。不要为回退删除监控表或覆盖当前元数据库。完整元数据库恢复另行安排停写窗口，先在隔离目录恢复和核对，再切换数据源配置；恢复数据库时应配套同版本应用和原加密密钥。

Windows 发布、状态检查和回退命令见 [本地运行说明](../../packaging/windows/README.md)。
