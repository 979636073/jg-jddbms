# 查询与 BLOB 性能阶段验收（2026-10-15）

本次范围为按目标字段读取、限量预览、流式下载、取消，以及大结果集和角色权限回归。测试地址为 `http://localhost:8080`，后端为本机 JDK 17，前端 Node 24，真实数据库为“本地 DM”连接下的 `TEST-TEST` 模式。测试没有修改真实账号的角色或真实连接的授权配置。

## 行为

- 列表查询继续返回 BLOB 占位标记，点击“查看”才读取目标字段。
- 数据库文件预览上限为 8 MiB；已知长度超过上限时仅读取最多 24 字节文件头。驱动不能提供长度时，最多读取上限加 1 字节，不返回完整正文。
- 下载通过独立接口直接传输二进制，服务端使用 8 KiB 缓冲，长度已知时设置 `Content-Length`。前端核对长度，失败或截断时中止写盘。
- 支持 `showSaveFilePicker` 的浏览器逐块写盘；其他浏览器使用 Blob 下载兼容方式，会在浏览器中缓存完整文件。自动化验证覆盖逐块写入逻辑、真实二进制接口和文件校验，没有人工操作原生保存对话框。
- “取消读取”同时中止浏览器请求，并调用取消接口。服务端按登录用户、连接和读取 ID 隔离，只取消对应读取并关闭其专用数据库连接。本地开发代理同步销毁被浏览器取消的上游下载响应，避免后端继续等待代理写出。
- 未保存的上传文件已存在于浏览器内，继续采用原上传文件下载路径；上述数据库流式读取不改变上传保存流程。

## 定位规则

表格优先使用原始行的 ROWID；控制台单表查询根据结果中完整主键或显式选择的 ROWID 定位。字段别名、模式名和复合主键可识别，值使用预编译参数绑定。表格编辑了主键但未保存时，查看文件仍使用原始行定位。

不再重新执行原查询并跳过若干行。排序字段变化、插入新行后，仍读取原主键指向的行；行已删除则提示刷新结果。缺少完整主键，以及 JOIN、UNION、DISTINCT、GROUP BY 等无法可靠映射的结果，明确提示查询原表并包含完整主键或 ROWID。这里定位的是当前行，不提供历史快照；原行内容被更新时读取更新后的内容。

## 本机测量

文件表为 `BLOB_LARGE_TEST_20261015`。以下是本机单次初验数据，受缓存、构建和其他进程负载影响，不作为线上性能承诺。

| 场景 | 响应量/结果 | 耗时 |
| --- | --- | --- |
| 11.3 MiB PNG 预览（ID 1029） | JSON 234 字节，正文为 null，仅有文件头 | 47 ms |
| 同图完整下载 | 11,879,648 字节，匹配 Content-Length | 620 ms |
| 16 MiB 文件下载（ID 1024） | 16,777,216 字节，匹配 Content-Length | 755 ms |
| PNG 下载（ID 1027） | 27,010 字节，SHA-256 与预览解码结果一致 | 51 ms |
| 空文件下载 | 0 字节 | 33 ms |
| 1,000 行查询，包含 BLOB 列 | JSON 48,467 字节，BLOB 全部为占位标记 | 179 ms |
| 连续 20 次 16 MiB 下载 | 共 335,544,320 字节；客户端逐块计数后丢弃 | 平均 178 ms，范围 158–291 ms |

宽表模拟组件初验挂载 179 ms；30 次滚动测量中两帧等待最大 164 ms，渲染单元格始终少于 600。该数据包含浏览器帧调度和主线程竞争，不能当作每帧渲染耗时。

内存测量在连续下载前执行一次 Full GC，再使用 `jstat -gc` 每 100 ms 采样，共 300 次；堆已用量为 S0U + S1U + EU + OU。起始约 71.16 MiB，采样最高约 183.55 MiB，末次约 135.63 MiB；测量后 Full GC 的 `GC.heap_info` 为 73,846 KiB（约 72.12 MiB）。这是单个文件大小下的采样结果，可能漏掉短时峰值，不包含浏览器、堆外内存，也不能证明任意并发下内存恒定。
